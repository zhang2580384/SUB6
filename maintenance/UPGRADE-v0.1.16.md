# SUB6 0.1.16

Administrators can disable request traffic metering in **System settings → Usage records**. The default is enabled. Disabling it hides both traffic reports and rejects direct reads. Gateways refresh the setting while idle. If the cached permission expires, a new request skips optional byte metering until a fresh setting is available. Requests already in progress and previously queued traffic events can finish. Usage records and billing keep their existing delivery behavior.

The model plaza now uses the DeepSeek V4 Pro reference price for the exact `deepseek-pro` alias. Channel prices and group multipliers still apply as configured. A continuation waiting on its original account gets the retry deadline for the specific mapped model when that model is temporarily cooling down. Manual pauses, invalid ownership and other admission failures keep their existing responses.

The public base is SUB6 `v0.1.15` (`33f1e4b60d3cf940344390307743a1f4831dccdf`). The targeted Ranxi changes come from #979 (`8e7a233de514f1d1ec49509d666d834540998206`) and #983 (`6177f4a3c9bad1bf82dafee03f4f684748b66107`). They add no migration or dependency. The optional traffic setting is based on SUB6 PR #7 (`8c3894983b553a6eec8e5d88371e163c0615ad8a`). The included background refresh bounds the lifetime of a cached collection permission. The migration fingerprint matches public v0.1.15. The managed updater checks the actual fingerprint and drains connections during a switch. A private installation with additional migrations needs a matching build. Rolling back the application to public v0.1.15 returns optional traffic collection to its previous default behavior. Preserve all transaction data and schema.
