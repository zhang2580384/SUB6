# SUB6 0.1.1：上游与升级兼容性

SUB6 独立版本为 0.1.1，基于 Ranxi 正式版 v2.21.2。
正式标签对象：`45b9d194e9e26062717aa7d9590383801f1a9e7e`；
正式版提交：`dbed7697aa56e76c6eb48c4914fa441496b67bdd`；
同步 production：`ccf997c73868083d96c0bec56e71c1a34d26c98a`。
该 production 仅在正式标签后更新 VERSION。相对上次锁定
`428448007faa9fd8cd715380a5fd132f3b1e9e5b` 为 12 个提交；
到正式标签为 11 个提交。本轮不另追浮动分支。

## 修复与审查

- 合入额度跳过不推进 `last_run_at` 的修复：无探测不能覆盖先前排队的 5xx。
  所有权、租约和事务边界保留；未增加扣款、外联、权限、依赖或 SQL 迁移。
- 保留真实队列/worker 回归与测试服务显式注入；排除上游新增工作流和脚本，
  它们依赖上游祖先、浮动 Actions 版本和远程诊断工具。SUB6 自有只读 CI
  使用固定 Actions 提交和一次性 PG/Redis 执行相应集成回归。
- 独立完整性复核修复品牌替换误伤：恢复 `X-Sub2API-Grok-Client-Tool-Cache`
  与 Copilot `X-Sub2API-Client-ID` 稳定协议头。前者仍接受 0.1.0 的 SUB6 别名，
  稳定头优先；后者两个名称均由可信 API key 身份覆写，不能继承伪造身份。
- 插件清单 JSON 和 Go 字段保持上游接口，插件兼容范围以 Ranxi 基线版本
  判断；SUB6 更新器仍比较独立的 0.1.1，不用被忽略的横杠后缀区分发行。
- 后台版本区、版本/检查更新接口、CLI 和 README 同时记录独立版本、
  Ranxi 正式版和精确同步 SHA。缓存或离线返回也使用运行中二进制的来源信息。
- 新增 `--migrate-only --migration-timeout=30m`：只执行原迁移 runner，
  不启动 HTTP、Redis 客户端或后台任务，不生成/轮换应用密钥。
  上限 6h；普通服务启动的原 10 分钟迁移超时不变。

## 从 2.19.5 的 17 个 SQL 文件

既有 SQL 正文未改变；不是按数字前缀去重。runner 按完整文件名排序，
对 `strings.TrimSpace` 后的正文做 SHA256，以文件名和 checksum 核验。
已知历史兼容白名单仍按文件名和两个精确摘要限制，不能手改数据库摘要放行。
多实例迁移的 PostgreSQL advisory lock 与所有 SQL 使用同一连接，
但它不阻止已经运行的业务 worker；不能把迁移锁当作业务排他锁。

带历史定制迁移的数据库可以保留源码中已不存在的记录；runner 不按数字前缀
匹配、不删除额外记录、也不会自动重放它们。验收计数应为实际基线记录数加
本次新增 17，而不是强制等于标准空库 419。遗留列/触发器需从副本 schema
单独核对；不能为了凑计数删除历史记录或重新启用已回退功能。仅增加
`groups.image_orchestration jsonb NOT NULL DEFAULT '{}'` 的旧定制列可保留；
该列的存在本身不启用已排除的编排代码，也不能据此推断其他历史 DDL 无副作用。

## 旧新短时并行的约束

结论：不宣称普通滚动升级安全。只允许在副本证明后，保留旧 **gateway**
处理已建立的连接，同时由唯一的新 full 生产调度状态；禁止新旧 full 同时
服务管理写入或执行全局任务。迁移期暂停账号/分组/价格/风控编辑，新增计费、
自动处置、daily 定时、AI 写控制、生图桥接均不启用。

- 迁移本身不是全部原子事务；每个普通文件一个事务，249 在事务外。
  新版本可能已完成部分迁移后失败。普通 gateway 启动同样会尝试迁移，
  role=gateway 不是禁止数据库 DDL 的开关；先完成唯一迁移，再启动网关。
- Redis 原有 key 类型、API key/余额缓存、队列和多数会话格式保留。
  新增 `openai_agent_owner:v1:` 所有权及 group-anti-distillation 命名空间；
  老网关不理解新增安全能力，不能在混版期间依赖这些能力。
- 调度空快照新增 `__empty__` ZSET 哨兵。老读取器找不到对应账号元数据时
  将缓存判为 miss，再走其配置允许的回退；这不是两版快照完全相同。
  新增投影字段影响图片授权、OAuth 降级和快速计费等行为，须由新 full 发布、
  按实际分组/账号/费率比对，不能由旧 full 持续覆盖。
- sticky account 新 CAS 不能约束旧版无条件 SET；旧连接可能回写绑定。
  保持既有会话粘性、legacy read/write 与 TTL 配置，核对旧新跨节点续接。
- API key 槽位新独立 TTL 必须在混版时等于旧共享 TTL；不同裁剪期限可能
  令旧/新节点提前删除仍活动的成员，造成错误排队或超发。
- refresh token 新实现原子读取删除，旧实现不具相同原子性；不得把登录/
  刷新请求分到两版 full。管理员入口只保留单一所有者。
- 不 FLUSH Redis，不清并发槽、账单幂等、WS 所有权和登录会话来“消除差异”。
  单独证明安全的可重建缓存才可做定向失效。

## 排空与切换预算（供副本/真实路由验收校准）

1. 完成配置/PG/Redis 备份和独立恢复；验证实际 migration checksum、
   密钥解密、旧版读取升级后的副本、账单幂等和真实 HTTP/SSE/WS。
2. 冻结管理写入并由唯一迁移进程完成迁移。若副本证明新 gateway 可安全读取
   旧 full 的快照，可先预热新 gateway 并切入模型 API 新请求，让旧 full 的
   请求排空后关闭旧 full，再启动唯一新 full。管理入口在所有权交接期间
   短时不可用；不能为预热而同时运行两个版本的 full。
3. 由新 full 接管任务并发布快照，至少检查各服务健康和 scheduler readiness；
   只测 `/health` 不代表账号/余额/价格/WS 路由正确。预留 60 秒稳定观察窗口。
   未证明上述过渡快照兼容时，采用先停旧 full、迁移、再启新 full/gateway
   的受控窗口。sidecar 继续由原独立服务承担。反代更新保留既有流连接的
   行为必须按实际配置验证；即便连接保留，后端仍必须持续运行到请求和回写结束。
4. 路由更新确认后留至少 5 秒传播窗口。HTTP/SSE 暂定 600 秒排空观察；
   已知更长请求按实际最大时长延长，不把它当成强制终止承诺。
5. 已建立 WS 不能搬到另一 TCP 连接。暂定 1,800 秒软排空预算，优先让
   活动 turn 完整结束；到预算仍活跃时显式选择延长或受控重连。客户端
   重连预算先按 10 秒验收，需验证其实际重试、resume 和幂等行为。
   无法承诺所有客户端无断线；不得对已经输出/计费的请求盲目自动重放。
6. 普通关闭默认只有 5 秒；部署 stop grace 必须覆盖请求排空、WS lifecycle
   和 usage worker 停止时间。`UsageRecordWorkerPool.Stop` 等待队列完成，
   容器强杀可能截断回写；停止前后核对持久 billing event、pending/retry、
   dedup 与 usage log，不能只看余额或 HTTP 200。

## 回滚与新账单

17 个文件以加列/加表、索引和配置转换为主，没有删除旧账单表。
旧版本迁移 runner 只核验自己包含的文件，不因多出的新迁移记录直接拒绝
启动；实际既有 checksum 必须先在真实副本匹配。未修改加密格式，仍需完整
保留 JWT、TOTP/凭据加密、会话和外挂密钥及原挂载；不可重建为随机新密钥。

优先回退应用并保留当前数据库/Redis，这样新发生的账单、余额与幂等记录
能够保留。前提是在真实副本证明旧二进制可读取该库，并冻结新价格、新限制
和新配置语义；不能仅凭表结构是向后加列就批准回滚。338 的映射/调度/extra
不会随二进制回退自动还原，342 的阈值和状态也不会。需要恢复单项设置时
对逐行快照做版本/CAS 核对，避免覆盖升级后轮换的凭据或新的管理员修改。

不默认整库恢复。恢复升级前快照会丢失切换后账单/充值/退款/配置变化。
仅在结构/数据确实不能修复且经过独立恢复演练时，才在停止写入、保全当前
库、明确新增业务流水的受控重放/对账方案后实施整库恢复；应用二进制回滚
不应触发自动恢复旧 PG 或 Redis。SQL 无通用 down 迁移，不试图删新表回滚。

## 必须保留的部署行为

- 商业 API key 账号转发不依赖 Google OAuth 客户端。确认只使用 API key
  的部署不把移除内置 OAuth 客户端作为阻碍；仍验证模型/分组/账号类型。
- 保留当前 256 MiB 入口、文本、WS 和上游读限制及代理限制，验证大请求
  内存成本，不在升级时无意恢复更小默认值。
- Grok 低 token 探活保留 `monitorProbe` 与原生 OAuth 证据，不能静默选边。
- 保留独立 SVIP sidecar 的数据库权限、手工总名额覆写和成功累计正向加款
  统计；它不随主应用重建，不重算/扣减账户余额。
- SMTP 配置、解析映射、宿主中转和证书须完整继承；旧容器 inspect 的
  ExtraHosts 可能不足以反映 entrypoint 动态补充，必须核对实际解析与中转。
- 站点品牌、账号/分组/渠道价格来自既有数据库，发布默认值不替代它们。
- 定制融合生图不恢复，图片桥接和 AI 自动写控制关闭；不自动启用收费、
  自动加款、风险通知或账号处置。支付仅以隔离假签名、重放、金额/所有权
  与幂等回调验证，不发真实订单或资金。
