## 审查结论与限制

对以下高风险路径进行了人工检查并结合回归验证，没有据此确认具体的恶意
植入行为。本次不是对约十二万新增行的逐行独立审计，也不覆盖每个上游、
每个真实支付商户、全部并发状态或未提供源码的第三方插件。测试通过和
扫描结果不能证明不存在恶意代码或其他安全缺陷。

| 路径 | 核查重点与结论 |
| --- | --- |
| `backend/internal/handler/payment_handler*.go`、`internal/payment/provider/` | 回调验证先于确认；检查各提供商签名/解密处理与商户身份，BEpusdt JSON 签名路径也纳入审查。真实生产支付端到端未执行。 |
| `internal/service/payment_webhook_provider.go`、`payment_order_provider_snapshot.go` | 优先使用订单锁定的提供商实例与创建时信息；多实例歧义不得随意回退到另一个商户。 |
| `internal/service/payment_fulfillment.go` 及订单/租约仓储路径 | 核对合法金额、币种最小单位、支付状态原子转换、租约和重复通知处理。拒绝 NaN/Inf 与不匹配金额。 |
| `internal/service/payment_easypay_recovery.go`、兑换/余额与退款路径 | 补单、所有权、重复入账和退款恢复采用已有受控流程；不通过回调中的用户参数决定充值归属。 |
| `internal/service/auth_service.go`、刷新令牌路径、路由与管理员中间件 | 检查刷新凭据原子消费、认证/管理权限边界和令牌处理；保留原有权限检查。 |
| `internal/service/plugin_package.go`、`plugin_manifest.go`、`plugin_runtime.go` | 检查清单/文件摘要、签名、路径与大小限制；运行时不继承宿主环境。但原生插件不是安全沙箱，可接收被授权的账号身份，安装启用必须单独评估。 |
| `internal/reauthruntime/`、`internal/mihomo/` | 下载固定仓库/版本，核对发行资产摘要后才执行；提取拒绝链接、设备、目录穿越与重复文件。本版补充拒绝跨平台绝对路径/反斜杠歧义。 |
| `internal/service/update_service.go` | SUB6 更新源固定到自身仓库，初始 URL 拒绝其他仓库、userinfo、query 和编码路径，强制 `checksums.txt`。GitHub 资产跳转不携带 API 认证；摘要不是独立发布者签名。 |
| `internal/service/ai_ops_service.go`、`internal/repository/ai_ops.go` | 写控制还需独立 `SUB2API_AI_OPS_CONTROL_ENABLED=true`，默认关闭；策略初始也未授权自动写入。模型输出不能自行越过宿主开关。 |
| 依赖、锁文件、迁移、CI、安装脚本与可执行资产 | 检查依赖差异和本地替换模块；关闭包生命周期脚本；旧自动安装器退出。CI 仅读权限，无生产 secrets、部署或二进制发布步骤。 |

插件仍保留上游内置 Ed25519 发布者公钥信任根，管理员安装该公钥签署的
特定原生插件后会信任其代码。这是明确的信任边界，不是已发现的后门证据。
本发行版未附带或执行闭源插件二进制。托管重新登录运行时仍保留上游独立
发行资产路径，其版本必须有匹配资产才能工作；SUB6 的 0.1.0 源码发布不提供
该二进制。相关能力不应被假定为已完成生产兼容验证。

动态模型价格、客户端版本元数据、IP 地理信息、验证码、OAuth 与支付 SDK
保留其各自公开服务目的地；这些请求应按实际使用功能和网络策略复查。
默认关闭的功能不表示所有后台元数据请求均关闭。没有把运行配置中的凭据、
生产域名、日志或数据库导出作为源码示例发布。

SUB6 清空上游凭证守护预填的外部探活/重登地址；未明确配置时拒绝启用或
选择远程重登引擎。探活会把 access token 发给所配置的服务，远程重登会
发送密码/TOTP，这一信任边界需要管理员单独审查。该裁剪不改写升级库里
已保存的地址，升级前必须人工检查原有设置。移除支付服务商邀请推广。

首次推送被 GitHub push protection 拒绝，命中上游内置 Google OAuth
客户端 ID/secret；没有绕过保护。公开历史重建时移除这些值及测试中的副本。
Antigravity 登录需显式提供 `ANTIGRAVITY_OAUTH_CLIENT_ID` 与
`ANTIGRAVITY_OAUTH_CLIENT_SECRET`；Gemini CLI 登录需
`GEMINI_CLI_OAUTH_CLIENT_ID` 与 `GEMINI_CLI_OAUTH_CLIENT_SECRET`，也可在
已有配置入口提供自有 Gemini 客户端。缺失时拒绝登录/交换；已有账户的
自动刷新也需要相应客户端，升级前必须单独准备，不能依赖原内置值。

## 保留与排除

- 保留主网关、WS/SSE、账号和分组调度、支付计费、管理权限及当前上游功能。
- 保留 Grok 低 token 探活修复。解决 Pelican 冲突时同时保留 `monitorProbe`
  与原生 OAuth 证据字段；未整批合入历史独立计费或已回退的生图分支。
- 保留独立 IP 白名单辅助服务：成功余额兑换及正数管理员加款累计，每 $100
  一个名额、上限 100；管理员可指定总名额或恢复自动；保持余额/计费不被改写。
  身份/所有权/Origin 检查、审计和失效关闭保留，认证 URL 不接受令牌跳转。
- 白名单的网络放行集合是共享集合，不把一个 IP 与一个 API key 绑定。
  防火墙同步器仅作为可选源码保留，未自动启用；部署须另行配置受限数据库角色
  和可信边缘代理。删除机器专用提权安装器与边缘配置脚本。
- 示例源构建配置保留 256 MiB HTTP/WS/上游读取上限；模型、文本端点和代理
  仍可能更低，大请求内存成本需另测。SMTP/隧道/WS 实例拓扑只属部署配置。
- 已回退的定制融合生图编排未合入、未恢复。上游 Codex 图片桥接默认 false，
  其兼容接口、账号需求、调度与资源成本不等同于该定制功能，需单独验收。
- 移除旧捐赠、赞助宣传、上游社区二维码与未核实截图；使用原供图
  `assets/community/sub6-qq-1126616545.png`，SHA256
  `e6d5a18db3440dbd545ec6f6023a67fca719e8b664011f784614229fc593255b`。
- SUB6 独立品牌与版本、更新仓库、源构建流程替换上游产品发布入口。
  内部 Go 模块/协议兼容标识、版权和必要上游来源链接保留。

## 数据库、配置与回滚

本范围新增 17 个 SQL 文件（249、250 和 333–342，其中若干前缀重复）。
迁移 runner 按完整文件名排序、以文件名/摘要识别，重复数字前缀不代表同一
迁移。本版未改写已经存在的迁移文件。

重点变化包括：长上下文/缓存写入 TTL 计费字段，API key 风控、逐 key IP
策略和取证数据，调度 outbox 重试与每日任务，AI 运维策略/提案与版本围栏，
OAuth 降级原生控制与质量 401 状态，自动加款邮件，以及支付提供商费率。
338 的 OAuth 配置转换和 342 的风控策略转换会改变持久化设置；默认开关
不能替代迁移前后逐项比对。`249_*_notx.sql` 的并发索引不在普通迁移事务内，
还应评估生产大表锁等待、重复数据与磁盘容量。

空库迁移及原 2.19.5 迁移集升级到当前均在一次性 PostgreSQL 18.7 上验证，
再次执行无误，合计 419 条迁移记录；升级样本余额保持不变。这不是生产副本
演练，不能覆盖实际历史 checksum、旧配置、规模和损坏数据的所有情况。

生产升级前必须先在脱敏/受控副本上验证迁移、支付与退款对账、计费价格、
OAuth 降级与风控、每日任务、缓存/WS 网关兼容和可选 sidecar 权限。
数据库升级与应用升级分开评估，不能直接把现有 PostgreSQL 数据卷挂给不同
大版本；示例 PG18 不是现有部署数据库大版本升级指令。

保留升级前匹配的应用、完整数据库/Redis 备份、配置、加密密钥和外挂组件。
先验证备份可恢复，再升级。回滚应用二进制不回滚 SQL 或设置转换；涉及模式/
语义不兼容时，应停止写入并整体恢复匹配备份，避免混用新旧 worker。
SMTP 主机映射、证书、隧道和代理状态不随源码发布恢复。
