# Wei-Shaw v0.2.24 integration review

The public SUB6 base is v0.1.14 (`0848e05be354dcaac4d76c68aa603581c79edc73`). The reviewed author release is Wei-Shaw/sub2api v0.2.24 (`5c2982a81b46e2142d0143d2f83c1ce9c4da1d24`). SUB6 v0.1.15 carries reviewed backports on the existing SUB6 source history.

* The gateway rejects ambiguous request fields before selecting an upstream or writing usage. Both HTTP and individual WebSocket frames are covered. An OAuth search permission denial returns 403 to the caller. It neither disables the account nor retries using a different account.
* The candidate preserves streamed image usage and buffered tool results, IDE context, per-turn reasoning effort and route-specific audio capabilities. The Grok edit endpoints accept up to five source images. A local input rejection does not consume an upstream request. The optional Exa search provider does not follow redirects with its API key.
* A usage query cannot replace a committed response field when their timestamps tie. It may still fill fields that have no value. An independently later observation can update the field. The weekly scheduling rule still requires valid evidence with a demonstrably later timestamp than any rejection.
* The existing accounting delivery, deduplication, platform quota and image balance reservation paths remain in place. Upstream batch settlement `2101f4f94` was excluded because its write set omits SUB6-specific accounting. The large-group fallback implementation `9c3280098` was excluded because its proposed cache-miss path conflicts with the SUB6 reader role and the bucket write token. These optimizations need separate integration tests against real storage.
* SUB6 commits an administrator-created user and all configured default platform limits in one transaction. Invalid stored settings abort creation. The signup flow keeps its existing policy. This intentionally differs from the upstream test that accepts creating an account after a quota write fails. The PostgreSQL regression checks rollback of both the user and its login identity, retry with the same email, an explicit zero limit and a missing policy. The quota integration CI job runs it against a disposable database.
* Historical fixes `76221c9cb`, `37a0f3870` and `98a44ba3f` now bind cached RPM limits to their group and make batch group policy writes atomic. Bulk updates preserve separate per-user model restrictions. Signed regional v1 snapshots retain their wire format. Tests cover failed updates, duplicate entries, outer rollback and group ownership.
* The upstream backports introduce no database migration, dependency or installer change. The updater uses the migration fingerprint already supported by v0.1.14.

Cache accounting also adapts author fixes `efc58486d`, `e6bde6b3c` and `bcb051213`. An explicit aggregate, including zero, takes precedence over partial lifetime details. Missing lifetime detail is billed at the short write rate. Raw observations remain available to usage logs. SUB6 retains its distinct OpenAI 30-minute and 12-hour prices, existing account-specific cache-as-input policy, and settlement/deduplication path. The user charge and the account cost both use the same allocation.

Gemini streaming backports `b0d60a8c8`, `27a61be4c` and `ce026a2cb` distinguish parallel calls with the same tool name in both Messages and Chat Completions. Repeated or final argument snapshots of a single call do not generate another call. The regression exercises protocol output in memory without invoking a tool.

This release keeps the existing saved routing settings and the v0.1.14 account routing policy.

The admission and composite-routing middleware now report the effective payload limit with the same message as the handler. The matched route selects the OpenAI, Anthropic (including System One), or Google response format. The same limit applies to compressed and ordinary requests. An early 400 omits the body contents.

The tool-schema sanitizer adapts Wei-Shaw `e7c587e14` to SUB6’s existing rules. It skips ordinary prose and reuses the end of a parsed history item. Tests compare the optimized string scanner against a bytewise reference and exercise escaped schema keywords. Older regex rewrites that reopen a closed object or replace its typed `additionalProperties` are excluded. An enabled tool therefore keeps the parameter constraints its caller declared.
