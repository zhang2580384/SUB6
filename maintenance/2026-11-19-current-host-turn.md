# Current Codex host turns

The HTTP Responses entrance serializes only a final standalone Codex delegation or scheduled event as a message. Readable OpenAI sessions that bridge downstream WebSocket to upstream HTTP use the same rule after admission, preserving the original client frame for owner and route checks. Older standalone events are kept as historical context and never stand in for the real result of a tool call. The entire event envelope and source are preserved, not asserted as human approval. Native WebSocket passthrough, opaque recovery, smart stateful sessions, prompts and scheduler settings are unchanged.

Reviewed HTTP ingress, tool pairing and the native named-output preservation path at Wei-Shaw `v0.2.23` (`5af9afb588c4b014b3df9db7d4073af1f8ae01b6`) and `main` (`2af3f1e15c98c893a89255a037f551046883b8c0`), and Ranxi `v2.22.0` (`4ba33f8713cbf6c6406e0f2639ffcc2ef1e31c87`) and `production` (`e687827fcb5c2bbb347dfb1d15f116c0ab0580c9`). Those paths retain separate automation/delegation scans and the automation continuation exclusion. This change does not merge upstream commits.

The HTTP and WebSocket-to-HTTP fixtures use the actual gateway with a deterministic provider. They distinguish a delivered task from replayed history, run a read-only client tool and verify that its result reaches the provider on the same owned conversation. The bridge fixture starts with an old heartbeat, then tests a later scheduled turn and an unrelated human turn. These tests cannot establish that any particular live model will choose to call a tool. Rolling back restores the previous translation. No database migration or billing change is required.
