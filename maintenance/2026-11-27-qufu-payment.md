# 趣付分账支付接入

基线为 SUB6 0.1.18，精确提交
`fb1401969363dcda35ec2e1d87cddcdc18f1c39b`。
实现提交为 `c79c86ef36b593c459f0d8b72fffd614ca627531`。
依据支付分账 API V1.0.0 实现独立 `qufu` 服务商。

## 行为和边界

- 支持支付宝、微信扫码及已开通的 H5 通道，服务商来源可独立选择。
- 按协议固定字段顺序、UTF-8 原始值和小写 MD5 签名，保留空值，拒绝重复字段。
- 下单及查单响应验签；通知使用原订单实例验签并主动查单。
- 对商户、订单、交易号、整数分金额、通道、币种和分账策略进行核对。
- 自动分账使用 `shareTag=1`、空 `shareFundList`，由平台处理商户预绑定账户。
  原有站内邀请返利保持独立，不转换为外部现金分账。
- 本地过期订单按原始到期时间保留三小时恢复窗口；超窗、取消、未付款失败
  需要人工核对。已经付款的履约失败可重试，重复通知只入账一次。
- 管理接口隐藏通信密钥；编辑留空保留。待处理及可恢复订单保护原商户配置。
- 文档未提供退款及关闭交易接口，禁用自动退款。取消本地订单不会关闭平台链接。
- 没有新增数据库迁移、项目依赖或 CI 发布逻辑。

配置、协议细节和回滚要求见 [接入说明](../deploy/qufu/README.md)。

## IPv6 下单兼容修正

实际网关会以业务码 `400005` 拒绝合法 IPv6 终端地址，文档没有注明这一限制。
新增实例级 `ipv6Compatibility=pseudo_ipv4` 显式选项，仅将发往该网关的
`terminalIp` 转为由原 IPv6 稳定生成的 Class E 合成 IPv4；IPv4 保持真实地址，
订单、审计和安全判断保留原客户端 IP。默认 `native` 及空配置不自动启用转换。
合成地址并非真实 IPv4，也不能用于定位、身份判断或当作无碰撞标识。

网关错误现在只保留受限六位数字业务码，帮助诊断；不回显未信任的平台消息或
原始响应，也不自动重试下单。前端可保存和切换兼容模式，接入说明记录其边界。
未付款网关对照确认两个扫码通道接受兼容地址；该证据不替代真实支付和分账验收。
