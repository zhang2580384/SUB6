# 趣付分账支付

SUB6 可通过趣付“支付分账 API V1.0.0”收取人民币充值与订阅款项。
服务商类型为 `qufu`，用户仍选择支付宝或微信，无需使用新的收银台。

## 分账范围

当前集成固定发送 `shareTag=1`、空 `shareFundList`。趣付按商户在其后台已绑定的
分账户处理分账。请先在支付平台完成对应通道的分账户配置。

SUB6 的邀请返利仍是原有站内额度：可冻结、转消费余额或由管理员登记线下提现。
邀请人没有趣付接收方绑定，因此本集成不会把邀请码或站内返利比例转换成外部现金
分账。两种机制直接叠加会重复支付，也无法对应返利冻结期、美元额度及退款。
这版不提供向任意合作方传入 `shareFundList` 的入口。

## 管理员配置

在“系统设置 → 支付设置”中启用支付功能，并在服务商类型中勾选“趣付分账”，
再到“服务商管理 → 添加服务商”选择“趣付分账”，按商户后台填写：

| 字段 | 用途 |
| --- | --- |
| API 网关 `apiBase` | 使用商户后台给出的 HTTPS 网关域名或完整 `/pay/gateway` 地址 |
| 商户 ID `mchId` | 趣付分配的商户标识 |
| 商户通信密钥 `merchantKey` | 32 位通信密钥，不能使用登录密码代替 |
| 异步通知 `notifyUrl` | `https://merchant.example.com/api/v1/payment/webhook/qufu` |
| 前端返回 `returnUrl` | 可选，`https://merchant.example.com/payment/result` |
| 支付宝通道 `alipayChannel` | `10` 扫码，或已开通的 `20` H5；默认 `10` |
| 微信通道 `wxpayChannel` | `11` 扫码，或已开通的 `21` H5；默认 `11` |

示例域名必须换成实际站点。通知和前端返回地址都不能包含查询参数。通道编码不是
分账线路 ID，不能将分账线路 ID 填入通道字段。后台已经开通扫码，也不代表 H5 已开通。

选中实际需要的支付宝、微信方式并启用实例。若同时保留易支付或官方通道，请在
对应支付方式的“服务商来源”中明确选择趣付；单一来源可自动选择。创建新实例不会
自动切走现有来源。用户端的支付总开关、金额限制、手续费和充值汇率继续沿用现有配置。

管理员读取配置时不会收到通信密钥原文；编辑时留空表示保留。沿用 SUB6 当前配置
存储方式，不代表数据库内配置已加密。存在待支付、处理中或三小时内过期的趣付订单时，
禁止更换商户、密钥、网关、通道或回调配置，也不能移除其原实例。轮换前先处理存量订单。

## 支付结果

请求使用 UTF-8 表单，按文档规定的字段顺序拼接原始值，生成小写 MD5。
空字段保留，不能改用字段排序签名，也不能对已 URL 编码的值签名。

下单成功只表示已取得支付链接。`GET /api/v1/payment/webhook/qufu` 对通知验签，
再使用原订单服务商实例主动查单。只有商户、订单、交易号、整数分金额、通道、币种
及自动分账策略匹配才进入现有幂等入账流程。成功通知返回纯文本 `success`；
验证、查单或本地处理失败时返回非成功响应，让平台重试。

本地过期订单按原始到期时间计算三小时恢复窗口，符合上述支付核验后可补单，
重复通知只入账一次。超过窗口、已取消或未付款失败订单需要人工核对，不自动
恢复；此前已经核验付款但履约失败的订单仍可重试。平台通知末尾的空 `&` 分隔
片段不影响验签，重复字段仍拒绝。

浏览器返回的 `orderNo` 仅用于查找订单；`orderStatus=2` 或返回金额均不能证明入账成功。
页面读取服务器保存的订单状态，已登录用户也可主动查单。支付成功不等同于分账户
已完成可提现结算，请在趣付后台核对分账订单和结算记录。

## 测试和发布

提供的 API 文档只有下单、查单和通知，没有退款、关闭交易、分账撤销接口。
因此本服务商禁用自动退款和用户退款入口，不伪造退款成功。关闭本地订单并不会
关闭趣付支付链接，取消后仍收到付款时应核对订单和平台账单。

先用独立测试站点和测试商户验证支付宝/微信下单、查单、成功通知、重复通知及
异常金额。完整验收还需真实支付和分账到账核对；不能仅凭生成二维码认为通过。
测试所需登录信息、通信密钥及请求证据应保存在源码目录之外，不能提交到 Git。

本次修改不新增 SQL 迁移或项目依赖。生产部署、通道切换及真实款项支付需要作为
实际上线步骤安排。回滚时必须处理新增趣付订单；旧版本不能验证趣付回调，不能
在未完成入账与对账时直接撤掉新回调入口。
