迁移服务器、变更代理与排错说明

一、应该填写哪个 IP？

请填写实际向我们发起 API 请求的公网出口 IP。下游使用 Sub2API 等中转程序时，通常是中转服务器的出口 IP；如果该程序经过 HTTP / SOCKS5 代理、VPN 或出站网关，请填写最终代理／网关的公网出口 IP，而不是服务器网卡上的地址。

「填入当前 IP」只检测当前浏览器的出口，可能是你电脑或浏览器代理的 IP。请在下游服务实际使用的网络环境中核实出口；容器与宿主机、浏览器与程序的代理配置可能不同。不要填写我们的服务器 IP、Cloudflare IP、内网 IP 或客户端展示的域名。

二、迁移或换代理，请按此顺序操作

  1. 先确认新出口：迁移服务器、更换机房／公网 IP、启停或切换代理、增加出站节点时，先确认新环境最终使用的公网 IP。
  2. 提前添加：保留正在使用的旧出口 IP，把新的出口 IP 添加到白名单；填写便于识别的备注。
  3. 等待生效：通常约 30 秒，刷新后确认新 IP 显示「已生效」。仅点击添加不代表已立即放行。
  4. 测试再切换：从新服务器或新代理出口，使用正常 API Key 发起一次请求；确认成功后再迁移业务。已有客户端继续使用 https://direct.example.com，需要 /v1 时自行追加。
  5. 最后移除旧 IP：确认业务稳定、旧出口完全停用后再移除旧记录。名额不足时先联系管理员，不要为腾名额提前删除仍承载业务的旧 IP。

三、多节点或动态代理如何处理？

同一服务有多个公网出口时，每个可能发起请求的出口都要分别加入白名单。轮换代理、动态住宅代理或经常变更 IP 的线路可能无法稳定使用直连；请使用固定出口，或继续使用原来的普通入口。

四、连接失败怎么查？

未放行的 IP 可能出现连接失败／超时，或收到 403 DIRECT_IP_NOT_ALLOWED。先核对真实出口是否变化、是否已登记且「已生效」、程序是否意外开启了其他代理。页面显示「名额不足」的记录不会按该账号的名额放行；请释放多余记录或联系管理员。

收到 401 时请检查 API Key；分组、余额、模型权限和上游错误仍按原有规则处理。白名单只解决入口访问权限，不代替 API Key，也不保证上游模型生成速度。请勿将长期 API Key 放进公开截图或分享给他人。

五、我们更换服务器，客户需要修改吗？

不需要。只要继续使用直连域名，平台更换服务器或修改域名解析 IP 时，客户无需修改接口地址，也无需重新添加原有出口 IP。请不要把客户端接口地址写死为我们的数字 IP；只有客户自己的实际出口 IP 变化时，才需要新增白名单。

一般访问继续使用原有入口。直连仅开放 API，仍需有效密钥。
